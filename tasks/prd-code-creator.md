# PRD: GitHub 代码创作及上传 Skill

## 概述

创建一个 Claude Code Skill，当用户激活它时，能够：
1. 询问用户想要创建什么样的开源代码
2. 与用户深入探讨技术实现和代码功能
3. 完整编写代码
4. 审核和测试代码
5. 最终推送到用户的 GitHub 仓库

## 目标

- 帮助用户快速创建并发布开源项目到 GitHub
- 提供完整的开发流程：讨论 → 生成 → 审核 → 测试 → 推送
- 支持本地和全局两种安装方式
- 确保代码质量：类型检查 + 测试 + 代码规范

## 用户故事

### US-001: 激活 Skill 并接收用户需求
**描述：** 作为一个用户，我想激活这个 skill 并告诉它我想创建什么样的开源代码。

**验收标准：**
- [ ] 用户可以通过 /code-creator 或类似命令激活 skill
- [ ] Skill 友好地询问用户想创建什么类型的项目
- [ ] 接收并记录用户的回答

### US-002: 深入探讨技术实现
**描述：** 作为一个开发者，我想和 skill 讨论技术实现细节，以确保生成的代码符合我的需求。

**验收标准：**
- [ ] Skill 提出结构化问题（语言、框架、技术栈）
- [ ] 同时允许自由对话来了解详细需求
- [ ] 记录讨论结果作为生成代码的参考

### US-003: 生成代码
**描述：** 作为一个用户，我想让 skill 根据讨论结果生成完整的代码。

**验收标准：**
- [ ] 根据讨论结果生成项目结构
- [ ] 生成所有必要的源代码文件
- [ ] 生成 README.md、LICENSE 等项目文件
- [ ] 代码能够正常运行

### US-004: 代码审核
**描述：** 作为一个开发者，我想让 skill 审核生成的代码以确保质量。

**验收标准：**
- [ ] 运行类型检查（TypeScript 等）
- [ ] 检查代码规范和最佳实践
- [ ] 提供审核报告和改进建议

### US-005: 测试代码
**描述：** 作为一个开发者，我想让 skill 测试生成的代码以确保功能正常。

**验收标准：**
- [ ] 运行项目自带的测试
- [ ] 验证代码能够正常构建
- [ ] 提供测试报告

### US-006: 推送到 GitHub
**描述：** 作为一个用户，我想让 skill 把代码推送到我的 GitHub 仓库。

**验收标准：**
- [ ] 询问用户 GitHub 仓库信息（已有仓库或新建）
- [ ] 初始化 git 仓库（如需要）
- [ ] 创建初始提交
- [ ] 推送到 GitHub
- [ ] 支持已有仓库的追加推送

### US-007: 安装选项
**描述：** 作为一个用户，我想选择把 skill 安装在哪里。

**验收标准：**
- [ ] 支持安装到当前项目 ./skills/
- [ ] 支持安装到全局 ~/.claude/skills/
- [ ] 每次询问用户安装位置

## 功能需求

- FR-1: Skill 通过 /code-creator 命令激活
- FR-2: 接收用户的需求描述
- FR-3: 提供结构化问题收集技术细节（语言、框架、依赖等）
- FR-4: 支持自由对话深入讨论需求
- FR-5: 生成完整的项目结构和代码
- FR-6: 生成 README.md、LICENSE、.gitignore 等配置文件
- FR-7: 运行类型检查确保代码质量
- FR-8: 运行测试确保功能正常
- FR-9: 支持推送到已有 GitHub 仓库
- FR-10: 支持创建新仓库并推送
- FR-11: 支持本地和全局两种安装方式

## 不在范围内

- 不自动创建 GitHub 账号
- 不处理 GitHub 认证（假设用户已有认证）
- 不支持复杂的 CI/CD 配置
- 不处理私有仓库（仅支持公开仓库）

## 技术考虑

- 使用 Claude Code Skill 格式编写
- 遵循 Claude Code 官方的 skill 规范
- 代码生成使用项目模板或从头创建
- Git 操作使用 git CLI

## 成功指标

- 用户能够在 5 分钟内完成从需求到推送的完整流程
- 生成的代码能够通过类型检查
- 生成的代码包含基本测试用例
